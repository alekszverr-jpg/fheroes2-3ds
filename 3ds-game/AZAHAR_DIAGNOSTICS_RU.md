# Azahar: рост длительности тестов и зависание ПК



Проверка 2026-10-13 выполнена по исходникам, истории Git, сохранённым логам и журналу Windows. Azahar не запускался.



## Что подтверждено



`test-menu-emulator.ps1` запускает весь накопленный набор интерфейсных проверок, а не только главное меню. Добавляются реальные диалоги с последовательностями вводимых событий, вложенные окна и сценарии боя. Каждый новый тест остаётся во всех последующих полных прогонах.



Оценка длительности: от первой датированной записи внутри игрового лога до времени изменения файла. Это приблизительная длительность игровой части; подготовка данных и последующая проверка изображений в неё не входят. Число маркеров SMOKE: PASS обозначает группы проверок, а не отдельные сценарии.



| Период | Маркеры групп | Примерная длительность |

| --- | ---: | ---: |

| 8 октября, ранние проверки | 4–9 | 7–28 с |

| Перед добавлением героя, 13 октября | 25 | 120–125 с |

| После добавления героя, 0.3.25 | 26 | 154–163 с |

| Последний успешный русский New, 0.3.26 | 26 | 181 с |



Примеры последних логов: `build/menu-tests/New/previous-20261013-063848-3034.log`, `build/menu-tests/New/previous-20261013-102956-6571.log`, `build/menu-tests/New/fheroes2.log`. Последний герой добавил примерно 30–40 с по этим прогонам. В testHero события содержат паузы 120 мс для касаний, 300+100 мс для кнопок, 600+100 мс для закрытия, 1200 мс для удержания. Такие ожидания есть и в других группах. Они обеспечивают устойчивую имитацию действий игрока, но суммируются; простое увеличение timeout не ускоряет набор.



Средний показатель draw_ms из последних сопоставимых успешных логов около 12–13 мс: 12.33 перед героем, 12.78–12.84 после героя, 12.75 в последнем русском прогоне. Это среднее отдельных отчётов, не взвешенное по кадрам. Сам draw_ms измеряет преобразование игрового кадра до предъявления буферов и ожидания VBlank. Это не полная стоимость кадра, не загрузка CPU/GPU Windows и не доказательство отсутствия сбоя эмулятора. Резкого роста этого показателя в последних логах нет.



Подготовка каждого запуска безусловно копирует оригинальные ресурсы: Data 45.1 МБ/15 файлов, Maps 26.7 МБ/137 файлов и подходящие OGG из Tracks2 (весь исходный каталог 46.2 МБ/42 файла), плюс свободные h2d и перевод. Эта схема существует с первого коммита и сама по себе не объясняет недавний скачок, но создаёт повторный дисковый ввод/вывод. Попиксельная проверка снимков выполняется в PowerShell после игровой части; она тоже не измерена отдельно.



Азахар использует профиль с frame_limit=100 и resolution_factor=1; признаков явно включённого неограниченного ускорения в сохранённой конфигурации нет. Последние запуски делались последовательно; после перезагрузки работающих экземпляров Azahar/компиляторов не было.



## Что не установлено



Причина зависания всего ПК не найдена. Windows записала Application Hang для explorer.exe в 16:09:07 и 16:09:19 и Kernel-Power 41 в 16:13:19 после принудительной перезагрузки. Эти события подтверждают зависание/нештатное завершение, но не называют виновника. В просмотренных событиях нет подтверждения сбоя видеодрайвера. Последний английский прогон не создал игровой лог; журнал Azahar оказался пустым. Нельзя приписать его остановку конкретному тесту внутри игры.



Свободные около 16 ГБ из 32 ГБ после перезагрузки не показывают расход памяти в момент зависания. Нет записанных замеров нагрузки, частот, температуры, памяти/подкачки и дисковых задержек Windows во время инцидента. Понижение приоритета Azahar не предотвратило повторение.



## Следующие изменения тестовой инфраструктуры



1. Разделить быстрый старт/отрисовку, отдельные группы диалогов и полный регрессионный набор. Для локальной правки выполнять только затронутую группу, полный набор запускать отдельно.

2. Записывать начало/конец каждой группы и отдельно время подготовки данных, эмуляции и проверки снимков. Тогда длительность измеряется прямо, а не по времени изменения лога.

3. Копировать неизменившиеся игровые данные только при первом запуске/изменении ресурсов; перевод и изменённые h2d обновлять отдельно.

4. До выяснения причины зависания автоматические запуски Azahar на этом ПК остаются приостановлены. Возможный диагностический запуск должен быть отдельно явно запрошен пользователем и ограничен одной короткой группой с записью показателей хоста.



Рост длительности набора объясняется расширением проверок. Полное зависание системы остаётся отдельной нерешённой проблемой; эти два вывода нельзя смешивать.



## Реализация разделения



Группы, отдельное время этапов, восстановление профиля после перезагрузки и пропуск неизменившихся ресурсов реализованы; см. [проверки](TESTING_RU.md). ARM/desktop/PowerShell и автономные проверки прошли. Azahar не запускался, новая длительность групп и причина системного зависания ещё не проверены.


## Короткие диагностические запуски по явному запросу

2026-10-13 пользователь попросил протестировать через Azahar. Последовательно выполнены только Startup и Building, каждый с лимитом 20 с и внешним ограничителем процесса. Full не запускался.

Startup прошёл: игровая группа 1.605 с, подготовка 0.533 с, загрузка/эмуляция 8.323 с, проверка изображений 2.446 с. Пользователь сообщил, что не заметил запуска эмулятора. Building прошёл: группа 5.216 с, подготовка 0.566 с, загрузка/эмуляция 10.294 с, проверка 0.053 с. Выборочные замеры Building: пик CPU 9.37% от всех логических ядер, рабочая память 594.8 МБ, private memory 1009.3 МБ. Это не полная память системы/GPU и не гарантия отсутствия проблемы в других нагрузках.

Логи: build/menu-tests/New/Startup/timings.json, build/menu-tests/New/Building/timings.json, build/azahar-Building-host.jsonl. Два коротких успешных запуска подтверждают работоспособность этих групп, но не объясняют прежнее системное зависание. Автоматические и полные прогоны по-прежнему приостановлены.

Полная проверка по отдельным группам 2026-10-13: 14 групп × New/ru, Old/ru и New/en = 42 результата PASS; engine self-test New/Old также PASS. Проверены старт/отрисовка, сообщения, сундук, повышение уровня, найм, рынок, подарки, герой, армия, книга, журнал, результаты боя, интеграция боя и строительство. Русские и английские снимки книги, карточки/строительства осмотрены. Исправлена только принадлежность снимка army-info-battle-bottom.bmp: его создаёт BattleIntegration, а не Army. Уже завершённый New/ru Army проверен по сохранённым маркерам, времени и свежим снимкам без повторного запуска. В остальных вариантах Army прошла обычным запуском.

Выборочный максимум процесса Azahar за эту серию: CPU 10.9% от всех логических ядер, working set 604.3 МБ, private memory 1004.9 МБ. Ограничители времени/нагрузки не сработали; пользователь не сообщал о повторном зависании. Это не замеры памяти/GPU всей системы и не установленная причина прежнего сбоя.
