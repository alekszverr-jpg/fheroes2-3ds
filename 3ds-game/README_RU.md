# Первая ARM-сборка fheroes2

## Preview 0.3.31: параметры замка на двух экранах

«Параметры» каталога строительства открывает отдельное окно 3DS: снизу два портрета кандидатов с именами и индикаторами доступности, кнопки разреженного/плотного строя гарнизона, «Назад» и «Сведения». Сверху — название замка, выбранный герой, портрет, класс/уровень, основные характеристики и причина запрета найма либо условие смены строя. Фон обоих экранов полностью закрывает карту. Первый тап другого кандидата выбирает его, тап выбранного/A открывает подтверждение 0.3.30; Y переключает кандидатов, D-pad перемещает фокус по шести элементам. B/удержание или «Сведения» открывает исходный readonly OpenDialog героя в адаптированном интерфейсе; B/удержание кнопки строя показывает исходное описание. Перетаскивание не запускает действия. «Назад»/L возвращает каталог строительства.

Окно возвращает только команду и указатель выбранного исходного кандидата. Castle::_openConstructionDialog получает кандидатов через прежний GetRecruits, вызывает DialogBuyHero/RecruitHero после подтверждения и возвращает прежний результат RecruitHero. После отмены найма открываются «Параметры». Строй меняется в Castle через исходный SetSpreadFormation только при BUILD_CAPTAIN; это условие проверяется и при доступности кнопок, и при исполнении. «Параметры» больше не переводит 3DS в старое полное окно строительства. Навигация замков/доход и все здания остаются в каталоге; главный экран замка ещё использует прежнюю компоновку.

ARM Release двумя потоками, desktop-синтаксис четырёх файлов, автономная инфраструктура (17 групп/29 компонентов) и применение патча к чистой базе проверены. CastleOptions прошла New/Old на русском и New на английском; регрессии Construction/New и HeroRecruit/New также прошли. Снимки осмотрены. Проверены оба кандидата/тап/Y/контроллер, пустые кандидаты, запрет строя без капитана и разрешённые команды строя с капитаном, readonly-герой/B/удержание, отмена перетаскиванием, Evil UI, родительские окна, кадр, область просмотра и поглощение отпускания. UI-тест не меняет деньги, список героев или строй и не вызывает настоящий RecruitHero; реальная смена строя/найм через полный приватный обработчик остаются для консоли. Монолитный Full не запускался.

Обновление с 0.3.30: заменить только `3ds/fheroes2/fheroes2.3dsx`; перевод не изменён. На New 3DS XL проверить строительство → «Параметры», обоих кандидатов, сведения/книгу героя в readonly-режиме, подтверждение и отмену найма, списание/появление героя, возврат в каталог, запрет строя без капитана, оба строя с капитаном и сохранение/загрузку. Аппаратная проверка 0.3.29–0.3.31 ожидается; физической Old 3DS нет.

## Preview 0.3.30: подтверждение найма героя

Обычное описание помещается целиком, длинное прокручивается D-pad вверх/вниз или движением стилуса по свободной области. Окно возвращает OK/CANCEL; вызов RecruitHero, размещение героя и списание выполняет прежний обработчик. Выбор двух кандидатов и прочие «Параметры» пока используют старую компоновку; главный экран замка остаётся следующим этапом.

ARM Release двумя потоками, desktop-синтаксис трёх файлов, автономные проверки каталога групп и применение патча к чистой базе проверены. Короткая HeroRecruit прошла New/Old на русском и New на английском (около 14 с на запуск); снимки осмотрены. Проверены настоящий DialogBuyHero, null-герой, разрешение по тапу/контроллеру, отмена по умолчанию, нехватка золота, лимит героев, удержание/вложенная подсказка, отмена перетаскиванием, прокрутка длинного текста, Evil UI и восстановление родительского окна/кадра/области/ввода без изменения денег и списка героев. ## Сборка

Из корня проекта в PowerShell: `./tools/build-game.ps1`.

Базовый fheroes2: `9754feff8501dbb69df95f3b999156a32eb8d7d3`. Для нового checkout применить `patches/fheroes2-3ds.patch` командой `git -C fheroes2 apply ../patches/fheroes2-3ds.patch`. Повторно к уже изменённому checkout патч не применять. Скрипт сохраняет местные изменения движка и проверяет базовый коммит. SDL2 и SDL2_mixer скачиваются при отсутствии и проверяются по закреплённым SHA; SDK устанавливается локально из `tools/sdk-lock.json`.

Отдельный CMake entry point использует upstream CMake targets engine/smacker и список исходников игры. Основная desktop-конфигурация upstream не изменена.

Исправления совместимости:

- 3DS использует существующую newlib-ветку endian-конвертаций.
- SDL-функции, возвращающие координаты через `int*`, используют временные `int` с последующим присваиванием полям `int32_t`. В devkitARM это разные типы, хотя оба 32-битные.
- Paths/config/logs используют `sdmc:/3ds/fheroes2`; ранний лог открывается до видео. FAT-пути не проходят POSIX case-insensitive resolver.
- Новый 3DS renderer записывает индексированные пиксели напрямую в RGBA8 framebuffer с правильным поворотом. Верхний экран показывает обзор, нижний — фрагмент, следующий за курсором. Touch использует координаты этого фрагмента и фиксирует его при удержании. Desktop renderer сохраняется.
- SDL gamecontroller включён; курсор всегда программный, L соответствует Escape. Intro-видео пока пропущены; создание аудиоустройства не блокирует меню при отсутствии DSP.

SDL2_mixer собран статически с WAV и встроенными OGG/MP3/FLAC декодерами; MIDI/MOD/Opus/WavPack отключены для первой сборки. Это не подтверждение работы звука или подходящей скорости декодирования на 3DS.

## Следующий шаг

8 октября 2026 пользователь сообщил о нормальной работе preview 0.3.0 после обновления на New 3DS XL. Первая физическая проверка панели карты пройдена без замеченных проблем; подробная проверка отдельных команд остаётся частью регрессии. Следующая разработка — контекстная панель боя. Следующие записи сохраняют историю предыдущих этапов.

Preview 0.3.0 реализует первую контекстную панель карты на нижнем экране (Y): предыдущий/следующий доступный герой, следующий замок, центрирование на герое, сохранение, файловое меню, завершение хода с подтверждением, закрытие. Стилус и D-pad/A, отмена B/L/Y; команды подключены к штатным обработчикам. PanelInput поглощает касания/кнопки и сохраняет защиту от отпускания после закрытия. Верхний экран продолжает показывать карту; эта панель не открывается внутри боя и модальных окон. Новые русские подписи добавлены в `ru.po`; при обновлении нужен новый `files/lang/ru.mo`.

Тесты New/Old Azahar прошли: реальные SDL touch events не становятся игровыми кликами, hit testing физических кнопок, защита отпускания, выбор каждой команды в модальной панели, недоступная команда, D-pad/A и снимки на двух экранах. Игровые команды в тесте выбора не выполняются — сохранения и завершение хода не создаются автоматически. Следующая физическая проверка — панель в матче, затем разработка контекста боя.

Пользователь дополнительно подтвердил ходы AI, бой и сохранение/загрузку на физической New 3DS XL. Основной игровой цикл в его сценарии проходит; перезапуск между сохранением и загрузкой отдельно не уточнялся. Следующая разработка — контекстная панель команд карты на Y, затем команды боя и адаптация двух экранов. Звук, длительные сеансы и физическая Old 3DS остаются отдельными проверками. Следующие записи сохраняют историю итераций.

Управление preview 0.2.4 подтверждено пользователем на физической New 3DS XL. Следующая разработка — контекстная панель команд карты на Y: выбор героя/замка, центрирование, сохранение, меню и завершение хода с подтверждением. Затем добавить команды боя и перейти к отдельным панелям двух экранов. Настройки чувствительности остаются дополнительной задачей. AI, бой, сохранение/загрузка, звук и длительная стабильность требуют отдельных проверок.

Preview 0.2.4 добавляет правую кнопку по неподвижному удержанию стилуса 550 мс. LocalEvent преобразует удержанное левое состояние в правое до upstream left-long-press (850 мс); отпускание остаётся правым, без дополнительного левого клика. Распознанное правое удержание фиксирует позицию и нижнюю область; жест прокрутки отменяет распознавание. Engine smoke проверяет настоящий путь SDL touch → LocalEvent, задержку, фиксацию, отпускание, отмену при движении и следующий обычный тап. Реальные игровые подсказки требуют проверки на консоли.

Preview 0.2.3 исправляет конфликт следования и adventure-map drag: стилус не запускает перетаскивание карты и её инерцию. Жест навигации распознаётся по физическому смещению от начала касания (10 пикселей); клики/long press после распознанного жеста подавляются, новый тап работает. Дрожание стилуса ниже порога не сдвигает область. Краевая прокрутка карты отключена для последнего стилусного ввода и возвращается при движении Circle Pad. Новый тест проводит SDL touch events через настоящий LocalEvent, проверяет обычный тап, дрожание, отмену клика после жеста, следующий тап и условия краевой прокрутки. Полный сценарий на загруженной карте этим тестом не подтверждён и требует физической проверки.

Preview 0.2.2 добавляет следование при движении стилуса за пределами центральной зоны. Начальное и неподвижное касание не сдвигают область; движения обновляют область перед преобразованием координат, чтобы курсор совпадал с физической точкой стилуса. Полный показ запрашивается при изменении области, даже если cursor hook не запросил обновление. Пользователь подтвердил удобное следование стику в 0.2.1; новое следование стилусу требует проверки на консоли. Тесты New/Old Azahar проверяют движение, соответствие координат, неподвижное удержание и границы.

Preview 0.2.1 реализует плавное следование по времени (90 мс постоянная сглаживания), центральную неподвижную зону 64×48, ограничение по краям и фиксацию при касании/удержании A/B. Камера завершает движение при остановившемся курсоре; после касания ждёт нового движения курсора. Исправлены координаты отпускания стилуса: SDL 3DS присылает нулевую точку, поэтому сохраняется последняя фактическая позиция. Engine smoke проверяет плавность, завершение движения, независимость от частоты обновления, фиксацию и координаты. Удобство нового поведения требует физической проверки.

Улучшения управления, интерфейса для двух экранов и необязательной стереоскопии запланированы в `UX_PLAN_RU.md`. По предложению пользователя основной режим сохраняет автоматическое следование нижней увеличенной области за курсором. Первая задача — улучшить плавность и точность этого следования, фиксацию при касании и корректный ввод/отпускание; затем контекстные команды и адаптация игровых панелей. Ручная прокрутка остаётся дополнительной возможностью.

После успешного входа в матч на New 3DS XL проверить движение героя, завершение хода и AI, бой, сохранение и повторную загрузку партии после перезапуска приложения. Уточнить карту и размер, проверить звук, стилус/кнопки в игровых окнах и длительную стабильность. Для оценки скорости AI нужны отдельные замеры: текущий FPS считает вызовы рендера, а не длительность игрового хода. Физическая Old 3DS остаётся непроверенной. Original Data/Maps/Tracks не включаются в распространяемый preview ZIP.
