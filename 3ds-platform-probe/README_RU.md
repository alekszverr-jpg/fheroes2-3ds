# fheroes2: тест платформы Nintendo 3DS, версия 0.1.0

Это первый технический тест перед подключением игрового движка. Он не запускает Heroes II и не требует её ресурсов.

## Запуск на New Nintendo 3DS XL

1. Распаковать папку `3ds` из ZIP в корень SD-карты.
2. Должен получиться файл `/3ds/fheroes2-probe/fheroes2-probe.3dsx` и соседний `.smdh`.
3. Запустить `fheroes2 platform probe` через существующий Homebrew Launcher.
4. Подождать 10 секунд. Сверху должна быть цветная сетка в уменьшенном виде и белые строки диагностики; снизу — увеличенный участок сетки с курсором. Цвета меняются автоматически. Красная рамка сверху показывает участок нижнего экрана.
5. Выполнить сценарий проверки ниже. Закрыть тест кнопкой Start.

Тест создаёт только собственный каталог `/3ds/fheroes2-probe/runtime-test` и дописывает `/3ds/fheroes2-probe/probe.log`. Повторный SD-тест перезаписывает только свой `roundtrip.txt`. Сохранения Heroes II и оригинальные игровые данные не затрагиваются.

## Управление

| Кнопка | Действие |
|---|---|
| Circle Pad | Перемещение курсора в виртуальном кадре 640×480 |
| D-pad | Перемещение увеличенного участка нижнего экрана |
| Стилус | Установка курсора в точку нижнего экрана; удержание обозначает левое нажатие |
| A | Левое нажатие: курсор становится жёлтым |
| B | Правое нажатие: меняется цвет курсора; событие записывается в лог |
| X | Запрос включения/выключения ускорения New 3DS |
| Y | Повторная проверка записи/чтения SD |
| Select | Показать/скрыть диагностические строки |
| Start | Выход в Homebrew Launcher |

Режим `BASE` после X не превращает New 3DS в Old: память и другие свойства остаются от New. Это только дополнительный замер без запроса ускорения. C-stick и ZL/ZR для теста не нужны.

Курсор и участок управляются независимо. Если курсор вышел за участок, его положение видно на верхнем экране; переместить участок D-pad, чтобы вернуть курсор на нижний экран. Плотные диагностические строки можно скрыть Select.

## Что проверить на устройстве

1. Верхний и нижний экраны правильно ориентированы; изображение не обрезано и не перевёрнуто.
2. В верхней строке: `NEW`, `LOG:OK`, `SD:OK`, `CPP:OK`, `SDL:OK`.
3. Circle Pad двигает курсор в правильную сторону и не двигает его при отпускании.
4. D-pad позволяет дойти увеличенным участком до всех четырёх углов кадра; красная рамка соответствует участку.
5. Касание в центре и у краёв нижнего экрана ставит курсор точно под стилусом. После отпускания нажатие сбрасывается.
6. A/B меняют состояние только при удержании. Y оставляет `SD:OK`.
7. Подождать не менее 10 секунд с `SPEED:NEW`, затем нажать X и подождать 10 секунд с `SPEED:BASE`. Не оценивать скорость fheroes2 по этому синтетическому кадру.
8. Закрыть крышку на 5 секунд, открыть и проверить возврат изображения/ввода. Записывать результат отдельно: пауза в логе может быть как сном, так и обычной задержкой.
9. Поиграть с тестом 2–3 минуты, выйти Start и повторно запустить.

Для следующего шага нужны файл `/3ds/fheroes2-probe/probe.log` и краткое описание любых проблем. Если приложение не запускается или зависает до появления картинки, достаточно описать, что произошло; лог может быть неполным.

## Что означает диагностика

- `FPS`: частота этого теста с ожиданием VBlank; не частота игрового движка.
- `CONVERT`: создание палитры, преобразование кадра в RGBA и копирование фрагмента.
- `DRAW`: загрузка текстур, программное уменьшение, оверлеи и показ обоих экранов.
- `heap_size`: назначенный heap приложения, не количество свободной RAM.
- `used_alloc` и `free_in_heap`: статистика allocator; свободные блоки внутри выделенного heap не равны всей доступной памяти.
- `linear_free`: свободная память linear allocator.
- `app_region_free=-1`, `valid=0`: runtime вернул противоречивые значения; по ним нельзя делать вывод о памяти. Такой случай наблюдался в Azahar.

## Сборка из исходников на этом компьютере

В PowerShell из рабочей папки:

```powershell
./tools/build-probe.ps1
```

Скрипт использует CMake/Ninja из имеющегося MSYS2 (`C:/msys64/mingw64/bin`) и SDK в `.toolchain/sdk`. Пути к CMake/Ninja можно передать через `-CMake` и `-Ninja`. При отсутствии SDK выполняется `tools/bootstrap-sdk.ps1`: официальные пакеты devkitPro загружаются в проект и проверяются по SHA256. При отсутствии SDL2 скачивается закреплённый коммит.

Используется локальный адаптер для native Windows CMake `cmake/native-3ds.cmake`; системные PATH, реестр и конфигурация MSYS2 не меняются. Стандартный devkitPro CMake entry point требует MSYS CMake, поэтому адаптер не следует считать официальным сценарием devkitPro.

Результаты: `build/probe/fheroes2-probe.3dsx`, каталог `dist/fheroes2-probe` и ZIP `dist/fheroes2-probe-0.1.0.zip`. Версии пакетов и SHA256 бинарника включены в пакет. Для полного воспроизведения использовать `tools/sdk-lock.json` и закреплённый SHA SDL2 из скрипта.

## Проверка в эмуляторе

В этом проекте использован установленный Azahar 2126.1.2, скопированный в `.toolchain/azahar` с отдельным portable-профилем `user`. Основной пользовательский профиль не используется. В нём тестовый лог лежит в `.toolchain/azahar/user/sdmc/3ds/fheroes2-probe/probe.log`.

В другом экземпляре Azahar открыть `.3dsx` как файл приложения. Эмулятор создаст лог в своём эмулируемом каталоге SD. Встроенный режим Old и успешный запуск не подтверждают поддержку настоящей Old 3DS.

## Зависимости и исходники

- SDL2: https://github.com/libsdl-org/SDL/tree/4c2d9014afda49553c76f7045529207bb593f9b5
- libctru: официальный пакет 2.7.0, https://github.com/devkitPro/libctru
- devkitARM GCC 16.1.0; полный список — `sdk-packages.json`.
- Исходники теста в проекте: `3ds-platform-probe`, `cmake`, `tools`.

Исходники прототипа включены в ZIP в каталоге `source`; лицензия GPL-2.0-or-later находится в `source/3ds-platform-probe/LICENSE`. Лицензия SDL2 включена в `licenses/SDL2.txt`.

Для автоматической проверки разработчиком: `./tools/test-probe-emulator.ps1 -Model New` и `-Model Old`. Требуется уже подготовленная локальная копия Azahar с portable-профилем. Скрипт временно создаёт `selftest.enabled` на эмулируемой SD, проверяет синтетические события через обработчик приложения, сохраняет `top.bmp`/`bottom.bmp` и лог в `build/probe-tests/<модель>`, затем восстанавливает конфигурацию. Этот режим не проверяет физические кнопки, стилус или сон консоли; в пакет для SD маркер не входит.

Физические проверки New 3DS XL и Old 3DS пока выполняются отдельно от проверки сборки/эмулятора. Это диагностический прототип.
